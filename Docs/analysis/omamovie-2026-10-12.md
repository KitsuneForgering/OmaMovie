# OmaMovie engineering reassessment — 2026-10-12

Scope: `feature/first-release` at `635ffad`, with one uncommitted `main.cpp` edit
kept untouched. Read source, tests, CI, ADRs, milestone records and measured evidence;
sampled critical paths rather than proving every branch. Classifications and source
anchors: [core inventory](omamovie-2026-10-12-core.md) and
[application inventory](omamovie-2026-10-12-app.md). The
[priorities](omamovie-2026-10-12-priorities.md) supply completion gates;
[performance evidence](omamovie-2026-10-12-performance.md) separates measurements;
[workflow gaps](omamovie-2026-10-12-workflows.md) rank user needs; the
[FilmCraft comparison](omamovie-2026-10-12-filmcraft.md) separates engineering evidence from breadth.

**Engineering readiness:** the core has a coherent path to a reliable local editor:
checked rational time, atomic typed commands, global timeline validation, bounded
project parsing, independent media libraries, CPU/Vulkan comparisons, recovery and
PR CI. The best tested subset is explicit timeline/time rules and native persistence.
The main unproved property is exact semantic state through arbitrary edit histories;
the round-trip helper compares a compact layout, not all persisted fields.

**Product readiness:** import, source marks/playback, timeline edits, stereo audio,
save/reopen and several export profiles exist. One representative source-to-output
task has partial checks, but the visible precision-edit workflow, selected decoded
frames/samples, write-boundary recovery and clean installed Omarchy run still lack a
complete v0.1 gate. Speed changes currently silence clip audio outside constant 1×;
the UI must make that consequence explicit before calling it an audiovisual edit.
This is a scope limit, not a demonstrated failure in the declared video-only behavior.

**Architectural debt:** `Session` coordinates import, timeline/UI mapping, playback,
project state and export; `main.cpp` owns a large GUI smoke; QML actions and delegate
names have some fragile routes. This raises change coupling and test friction. Extract
only a touched responsibility with a clear owner and regression, starting with the
smoke driver or source/edit-to-view mapping. The 60-line file target is an inventory
metric; splitting every text file does not establish better ownership or behavior.

**Performance evidence:** 5,000-clip UI edits met the proposed interaction gate
after delegate virtualization; trim drag at 5,000 clips had p95 24–27 ms, with an
unexplained 150–195 ms frame-side stall. Warm project open/save at 5,000 clips was
35/22 ms in a library benchmark. A 10,000-file recordings scan took ~15 ms warm.
These runs do not measure cold storage, multilane 10,000-clip projects, three-hour
source workflows or 1080p long export. Keep sorted vectors and current UI-thread
scan until a representative workload fails its budget.

**Verification today:** `make -j2 test` could not build the uncommitted `main.cpp`:
its new smoke diagnostic passes `const QQuickItem*` to a mutable-pointer lambda.
Existing Debug binaries passed nine CTest suites; CTest's app launch failed with a
display error, while direct `build/debug/tests/app_tests` passed all 40 tests.
These are local observations, not a clean CI claim. The PR workflow runs GCC/Clang
Debug/Release/ASan/TSan, lint and bounded parser fuzz; CMake currently excludes the
app and Session tests from ASan/TSan builds, and the real-window GUI smoke is manual.

**FilmCraft comparator:** its [repository](https://github.com/storytold/filmcraft)
shows broader UI and owned codec/container surface; its
[gap inventory](https://github.com/storytold/filmcraft/blob/main/docs/gaps.md) reports
Linux/runtime, real-media corpus and PR test-CI gaps. OmaMovie delegates
codec/container correctness to FFmpeg but must still validate timestamp, ownership,
interop, output and recovery boundaries. Neither editor was run in a matched task
here; relative speed, fidelity and professional readiness remain unmeasured.
Rust reduces some memory hazards; C++ requires lifetime discipline and sanitizers.
