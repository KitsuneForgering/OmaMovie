### M9 — Interop and color

- [ ] `libs/project-ir` + importer framework + import report + `Docs/interop.md` with levels per format. *Started (2026-10-13)*: ADR-0008 accepted (IR shape; OTIO read by an own reader on simdjson, no new dependency). `libs/project-ir` holds the IR (tracks of clips, gaps and transitions in source time, opaque objects for anything unrepresented), `ir::validate` (unique media ids, known media, clips inside their media compared exactly across timebases, no negative durations; `tests/project-ir`) and the import report with §16.5 levels; `Docs/interop.md` lists every format at no proven level. *OTIO reader (2026-10-13)*: `libs/importers::import_otio` (bounded: 64 MiB, depth 64, 100,000 items) reads the pinned schema subset into ProjectIR with a report; `tests/importers` checks exact NTSC times, fractional frames, shared media, kept opaque effects/generators and refusals; `fuzz_otio` ran 2,000,000 inputs clean. Building it found `make fuzz` broken for the cube and subtitle targets (an `error_strings.cpp` split); fixed. *Converter (2026-10-13)*: `project::from_ir` builds a document through timeline commands with an app-supplied media resolver (this library cannot probe), tested on a hand-built IR (`tests/project/test_from_ir.cpp`). *CLI (2026-10-13)*: `oma-project import FILE.otio` prints the report from the same importer and converter, with media durations from the file and files checked but not probed (`tests/project/test_cli.sh`). A `convert` command waits for the probe-to-library mapping, which lives in `Session` today, to move somewhere the tool and the app can share. *In the app (2026-10-13)*: Import OpenTimelineIO… (palette) reads, probes each media file with the library import's rule (now `media_entry`, shared) and opens the result as an untitled, unsaved project; the import report opens when there are notes (`tests/app/test_import_timeline.cpp`, GUI smoke). Open: an `oma-project convert` command (the probe rule is app-local), reporting opaque objects the native format does not keep, and fixtures from real application exports.
- [ ] OTIO pilot first using a pinned library/schema and actual versioned exports; evaluate FCPXML, EDL and Kdenlive subsets with fixtures. For FCPXML, pin an exported version, cover both `.fcpxml` and applicable `.fcpxmld` bundles, and check rational timing, connected clips, gaps, media references and unsupported objects before claiming any support level. Report floating-to-rational conversion loss and unsupported effects.
- [ ] `oma-project diff | convert`. *`diff` (2026-10-13)*: compares the canonical dumps of two projects with Myers' O((N+M)D) line diff, keeping only each step's diagonals (O(D²) memory) and refusing past 2,000 edits rather than growing without bound; a property test checks 5,000 random pairs against a dynamic-programming LCS (minimal and consistent scripts), and a deliberate mutation of the backtrack fails it. Output lines are `-N:`/`+N:` with line numbers, exit 0/1/2 like diff(1). Open: `convert` (waits for a shared probe rule), and field-path output for reverse engineering of external formats.
- [ ] Color management presets, `.cube` LUTs, scopes; HDR gated by independent vectors and an actual display/preview/export contract. `.cube` LUTs exist (ADR-0012). *Luma waveform (2026-10-13)*: the color drawer's More view shows a luma waveform (BT.709 Y' of the display-encoded picture) of the frame at the playhead, rendered at 256×144 by the CPU reference compositor from the same render graph as the viewer, so grading, looks and layers are measured; it refreshes 120 ms after the playhead stops or an edit, never while playing, and is hidden below 760 px. `tests/app/test_scopes.cpp` checks levels on a synthetic picture (black, white, pure green at 182) and the session path. Open: RGB parade and vectorscope, a measured refresh cost, color management presets and the HDR gate.
- [ ] Conditional **audio-role and stem** pilot for a project that must deliver dialogue and music separately. Keep the current stereo program mix as the baseline; add user-visible role labels to audio-bearing clips/tracks only if they make this hand-off clearer than muting and exporting twice. Decide how clip role, track mute, connected audio, fades, EQ/noise reduction and transitions contribute to each stem; snapshot the routing with the export request. Verify that independently decoded stems recombine to the program within declared gain/codec tolerances and that no source channel is dropped or duplicated without an explicit downmix rule. Start with two stereo roles; defer surround, arbitrary buses and a mixer UI until a real delivery task needs them. Profile simultaneous decode/mix cost and bound exported files and memory ([Final Cut Pro role exports](https://support.apple.com/en-ca/guide/final-cut-pro/verc9c84cdbc/mac), [Resolve Fairlight guide](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-18-Fairlight-Audio-Post.pdf)).
- [ ] Conditional nested-sequence pilot only if a repeated-intro, chapter or multi-output task shows a material advantage over copying editable clips or exporting/reimporting a segment. Begin with two named sequences and one reference, not unrestricted nesting. Define source-time mapping, audio/caption and effect ordering, edit propagation, cycle rejection, undo, cache invalidation and missing-media behavior before changing the native DTO or ProjectIR. Compare edit time and output fidelity with the simpler alternatives; independently decode exports before claiming reusable sequence support. Kdenlive documents live references and multiple sequences, but that establishes availability, not demand in OmaMovie ([Kdenlive sequences](https://docs.kdenlive.org/en/cutting_and_assembling/sequence.html)).
- [ ] Conditional export queue and multi-output pilot after one-export snapshot correctness and long-export recovery pass M7/M10. Test a real task that needs two aspect ratios or separate chapter outputs against exporting each version manually. Every queued job must pin its own project snapshot, media/effect dependencies, caption snapshot, destination and settings; edits or project switches must not change it. Bound concurrent decode/encode, RAM and disk on the Intel target; verify each decoded output and sidecar independently, including cancellation, duplicate destinations and a failed job that does not corrupt the next one. Do not infer a speedup from queueing: it may only save operator time ([Kdenlive rendering and job queue](https://docs.kdenlive.org/en/exporting/render.html)).
