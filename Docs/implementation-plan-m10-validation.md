### M10 — System validation and release gates

Run against features selected for the Intel/software v0.1 scope. Reuse `make test`, sanitizer builds and the
existing `make fuzz` targets for project JSON and `.cube` LUTs; extend them for new
untrusted inputs. Keep small deterministic regressions in CI and longer hardware runs
as recorded release checks.

- [x] **Fuzzing and parser limits:** add coverage for the media probe and each implemented importer (including the shipped SRT/VTT importers). Seed valid, truncated, oversized and boundary inputs; cap input size, allocation and work. Run with ASan/UBSan, retain every reproducing crash as a regression fixture, and reject invalid input cleanly. Keep the existing project/LUT corpus and exercise project migrations as versions are added. *Done (2026-10-13)*: `fuzz_probe` feeds untrusted bytes through `oma::media::probe` with the media library instrumented (coverage, ASan/UBSan) and FFmpeg as the system library, so it checks OmaMovie's handling of what FFmpeg reports, not FFmpeg's demuxers; `make fuzz` bounds it by time as well (`FUZZ_PROBE_SECONDS`, default 600: ~125 runs/s). It found two bugs, each kept as a corpus seed and a `tests/media` regression: a Matroska file declaring negative durations (now unknown) and an undefined color-space value loaded as an FFmpeg enum, which is UB (color fields are now read as integers and undefined values become unspecified, also for decoded frames). `fuzz_project` was broken since `libs/project` gained `project-ir` (restored) and now has seeds for formats 1–7. Recorded campaign after the fixes, clang 22, ASan/UBSan: cube, project, SRT/VTT and OTIO 200,000 runs each; probe 176,206 runs in 1,800 s; no findings. CI runs `make fuzz FUZZ_RUNS=500000` with the default probe budget.
- [x] **Stateful edit properties:** follow [QA timeline properties](implementation-plan-qa-timeline.md): seeded valid timelines and command streams across split/trim/move/ripple, speed maps, connected clips and undo/redo. Check independent invariants and rejected-state preservation after every step; compare every semantic state through full undo/redo and save/reload. Preserve the seed, exact replay log and minimized deterministic regression for each finding. Start with a bounded fast subset; expand command coverage without replacing M5 examples. *Done (2026-10-13)*: `tests/timeline/property_*.cpp` generates 21 step kinds (placements, split, trims, ripple delete/move, roll, slip, slide, cross-track move, constant speed, ramps, reverse, freeze, connect/disconnect, undo/redo) by position over the shared fixture, with rejected steps by design. After each step it checks independent structure and media-extent oracles (exact 128-bit fractions, not `validate()`), unchanged state/revision/history after rejection, exact states on every undo/redo against the saved S0…Sn, monotonic clip IDs and a final full unwind/rewind; `tests/project/test_edit_round_trip.cpp` saves and reloads every accepted state. Reports print seed, generator version, replay command and a delta-debugged log (`OMA_PROPERTY_SEED`, `OMA_PROPERTY_RUNS`, `OMA_PROPERTY_STEPS`); a coverage floor stops a generator that only produces rejections. `make test` runs 48 seeds × 60 steps; 3000 × 200 and 1000 × 150 passed locally. Findings fixed with deterministic regressions (`test_no_op_edits.cpp`): edits that changed nothing (disconnecting an unconnected clip, zero trims/slides, same speed, moves to the same place) left empty Undo entries, and connections the Editor later dropped (same track, chained) were recorded. Transitions, effects/keyframes, markers, captions and detach are not generated yet.
- [ ] **PR gate and application sanitizers:** keep the current GCC/Clang × Debug/Release/ASan/TSan matrix, format/tidy and parser-fuzz jobs; require their successful checks for merge through a GitHub ruleset. The current workflow triggers on PRs but `master` has no protection/ruleset (checked 2026-10-12), and `cmake/OmaProjectTargets.cmake` omits app/Session tests in ASan/TSan. Add a bounded, stable application sanitizer subset and state its hardware exclusions; do not claim whole-app coverage from library-only jobs. *Partial (2026-10-13)*: the app/Session tests (62) now build and run in the ASan and TSan builds (`make BUILD=asan|tsan test`), passing 5/5 repeated TSan and 4/4 ASan runs locally (GCC 16; the TSan subset also passed with clang 22). Making them meaningful took: one UI hand-off helper (`post_to_ui`) that tells TSan what Qt's uninstrumented event queue orders (678 reports, almost all that hand-off, before it); app tests isolated from the desktop's Qt theme, input method and session bus, as in CI; Session posting no desktop notifications unless the app opts in. Exclusions, recorded beside each suppression: Qt, GLib, libdbus and fontconfig are not instrumented (their internal threads are suppressed by library, never `libQt6Core`/`libglib`, which carry OmaMovie's UI-thread work); fontconfig's lifetime caches in LSan; the proprietary NVIDIA Vulkan driver is disabled in sanitizer runs (outside v0.1; ~10 s start and a TSan thread-registry abort); debuginfod is off so symbolization stays local. Open: the GitHub ruleset requiring these checks on `master` (repository settings, the owner's action).
- [ ] **End-to-end workflow tests:** automate import → edit → save → reopen → preview → export using generated video/audio and a real Omarchy recording. Check selected frames, cuts/transitions, audio continuity and A/V sync with an independent decoder; exercise keyboard navigation and a headless/offscreen GUI smoke path where possible. Run software fallback in CI and the GPU path on actual hardware. *Partial (2026-10-12)*: `tests/app/test_edit_workflow.cpp` exercises marked source placement, precise-edit undo, save/reopen and a 35-frame export checked through `ffprobe`; `test_export_snapshot.cpp` verifies the 30-frame output and original caption after an immediate project switch. The Intel/Omarchy GUI smoke passed. *Added 2026-10-13*: `test_recording_workflow.cpp` runs import → split → ripple delete → save → reopen → software export on a file shaped like an Omarchy recording (generated: H.264 High 1080p60, time base 1/15360, AAC 96 kHz running past the video, and a silent copy); ffmpeg confirms every exported frame's picture and, by a per-frame tone, its sound (loudness steps did not survive AAC). `test_real_recording.cpp` runs the same flow on a real recording given by `OMA_REAL_RECORDING`: three local captures passed ([evidence](Research/evidence/2026-10-13-m10-real-recordings.txt)). The flow found an export colour bug, fixed under ADR-0006's amendment and held by `test_export_transfer`/`test_export_levels`. *Keyboard workflow (2026-10-14)*: the GUI smoke now marks a source range (Shift+O, I, Shift+Right, O, Escape), appends it (E), splits it (Ctrl+B), deletes the part under the playhead (Delete), saves (Ctrl+S), undoes back (Ctrl+Z) and plays (Space) with real key events; file dialogs are left out. It found a defect: a slider in a drawer that closed while focused (Noise reduction in Volume) kept the keyboard focus, so I did nothing and the arrows changed the hidden noise reduction instead of stepping frames. The window now takes the focus back when the focused item hides; without that the new step fails. *Headless GUI smoke in CI (2026-10-14)*: Qt's offscreen platform cannot host a Vulkan surface, so a `smoke` CI job (`scripts/ci-run.sh smoke`) builds the release app in the Arch container and runs the whole GUI smoke, keyboard pass included, on headless sway with lavapipe; run locally in that container it passed in 4 min 25 s on llvmpipe. This is the software-Vulkan path; the Intel path stays a local run.
- [ ] **Effects contract tests:** exercise schema bounds and unknown/missing versions, ordered stack evaluation, bypass/mix and shipped keyframe timing, undo/redo and old-project migration. Compare CPU/GPU output and independently decoded export at selected frames for shipped built-in effects and presets; record pass cost and memory at 1080p and 4K on each validated device. A missing pack must leave the project recoverable and never produce a silently altered export. *Export gate (2026-10-14)*: export already refused any effect this build cannot render, but its notice said to remove or turn it off, and turning it off did not help: the check ignored `enabled` and hidden tracks. It now blocks only an enabled unknown effect on a visible video track and names it (`unrendered_export_effect`, `tests/app/test_missing_lut.cpp`); a bypassed or hidden one renders as made, as the missing-LUT check already allowed. *Every look (2026-10-14)*: the GPU/CPU checks covered Vignette, Vintage, Cool and detail inside a busy scene; `gpu_matches_cpu_for_every_look` now renders each shipped look alone at full and half amount and compares it with the CPU reference (Black & White, Sepia and Warm had no GPU check). Presets are rows of these looks composed on the CPU, so they add no shader path. Pass cost (2026-10-14, [evidence](Research/evidence/2026-10-14-m10-effect-pass-cost.txt)): on the Iris Xe looks cost nothing measurable, blur is cheap (it reduces first), and sharpen costs about 4-5 ms at 1080p and 7 ms at 4K; an identity full-size copy in the detail chain was removed (sharpen 1080p mean 5.1 -> 4.3 ms). Open: decoded-export checks per effect and memory per pass.
- [ ] **Failure and recovery tests:** inject errors at save/autosave and export write/rename boundaries and any sync boundaries actually implemented, plus full disk, missing/moved media or LUT, corrupt cache, cancelled jobs and interrupted processes. Verify acknowledged project data survives, recovery is explicit, incomplete exports are not presented as finished, and workers/resources shut down without hangs. Reuse M7's save-failure and long-export checks rather than duplicating them. *Added 2026-10-12*: `test_export_crash.cpp` kills the publisher at all five publication checkpoints, verifies both public files after recovery, checks a restarted Session's recovery action, hides live locked stages and rejects reuse of an unresolved destination. *Save boundaries (2026-10-14)*: `tests/project/test_document.cpp` now also fails a project save at the write (EFBIG from `RLIMIT_FSIZE` in a child process) and at the rename (the destination is a folder), beside the existing temporary-file refusal: the previous file stays byte for byte and no temporary remains. The file and folder `fsync` failures need a syscall seam or a faulting filesystem and are not injected. Resource stress remains open.
- [ ] **Concurrency and lifetime stress:** loop play/pause/seek, project switches, viewer resize, decode-path fallback, export cancellation and shutdown while decode/compositor/audio jobs run. Check bounded queues, deadlock timeouts and device-resource lifetime under TSan/ASan and Vulkan validation layers; test simulated device loss where supported. Record the tested hardware; do not make unavailable AMD, NVIDIA or hybrid devices a release prerequisite. *First stress pass (2026-10-14, Intel)*: `tests/app/test_session_stress.cpp` runs 200 seeded play/pause/seek/shuttle/step/split/undo/redo intents a few ms apart, cancels a 20 s export mid-way (58 ms to stop in debug, nothing published) and destroys a Session while it plays and exports (334 ms in debug, no temporary left); all pass under TSan. TSan found two things on the way: thumbnails scaled with `QImage::scaled(Smooth)` on the import job spread over Qt's global thread pool, a race inside Qt that the suppressions cannot cover, so thumbnails and edge frames are now scaled by swscale in the RGBA conversion (`copy_rgba_scaled`, also no full-size copy; cache key `thumbnail/v2`); and libavfilter's noise-reduction threads needed the same suppression as the other uninstrumented FFmpeg libraries. Project switches (2026-10-14): 40 seeded switches between a saved project, a new one and a fresh import, interleaved with playback and started exports, settle to the last request's single clip; clean in debug, three TSan runs and ASan/LSan. Validation layers (2026-10-14, [evidence](Research/evidence/2026-10-14-m10-validation-layers.txt)): the gpu, compositor and app suites, stress included, run with core and synchronization validation with no error and no sync hazard; best practices only flag known small dedicated allocations and the conservative layout barrier. The live window: 10 s of playback is clean, but each of the GUI smoke's 7 `grabWindow()` calls is followed by swapchain sync hazards in Qt's frame, with or without hardware decode, while Qt-only grab controls are clean. A minimal control reproduces it with only OmaMovie's `gpu::Device` adopted by Qt (10 grabs, 10 hazard triples; Qt's own device: none), and disabling OmaMovie's frame hooks changes nothing, so the trigger is grabbing on the adopted device (normal use never grabs). A bisect ruled out the optional extensions and features (a minimal device still reproduces it). Open: the instance/queue setup or Qt's grab path for adopted devices (a Qt report), and viewer resize in the loop. *Device loss while playing (2026-10-14)*: the GUI smoke now marks the device lost 300 ms into playback with hardware decode on; the viewer shows the notice, the audio clock keeps advancing, pause works, and an edit is saved (two consecutive runs).
- [ ] **Audio and temporal boundaries:** compare `TimelineAudio` output across different block partitions, seek/restart and frame-aligned export boundaries with exact pulse/automation fixtures; compare preview and export PCM where their declared processing agrees. Test 23.976/29.97/59.94, 44.1/48 kHz, VFR and long source offsets at UI↔rational and keyframe interpolation boundaries. Treat drift and precision loss as hypotheses until a focused case fails. *Block partitions (2026-10-14)*: `tests/playback/test_block_partition.cpp` renders linear volume keys, a cut with an EQ'd clip dissolving in and a 2x clip, and a noise-reduced clip, in fixed 1024-sample blocks and in seeded irregular blocks (1 to 4096 samples, and 1600): identical samples in every case, so no partition dependence was found; the exporter's own per-frame blocks at 23.976, 29.97, 30 and 59.94 fps match too, so preview and export feed the encoder the same PCM. *Found (2026-10-14)*: a sequence timebase that holds no 48 kHz sample (1/30, which a project without one is read as) made the mixer assume one tick per sample and play a 1 s clip for 30 samples while reporting success; it now renders silence and returns an error (regression test in the same file). Open: VFR/long-offset cases.

- [ ] **Sustained workload and regression measurements:** run the [long-form gate](Research/long-form-editing.md#proposed-gate-before-optimizations) plus repeated open/edit/preview/export cycles. Record frame drops, A/V drift, p50/p95/p99 and worst interaction/seek times, peak and end-of-run RAM/VRAM, file descriptors, cache/disk use and export correctness. Compare against a committed baseline for the same machine, driver and media; investigate growth or regressions before release. *Bounded pass (2026-10-14, [evidence](Research/evidence/2026-10-14-m10-sustained-cycles.txt))*: `tests/app/test_sustained.cpp` repeats open/split/play/save/export/close and checks descriptors and resident memory per cycle; over 30 cycles descriptors stay constant and memory settles near 150 MB after about nine. Open: the long-form gate itself, latency percentiles, VRAM/cache/disk and a committed per-machine baseline.

**Done when**: deterministic and sanitizer suites pass in CI; bounded fuzz campaigns
pass for each shipped untrusted parser within a recorded run budget, with found crashes fixed or the affected input support removed; the edit-sequence,
workflow, recovery and concurrency checks pass on their declared paths; long-form
results and the tested hardware are recorded with fixtures, seeds, commands and versions.
Unavailable hardware and unshipped pilots are outside this gate. A failing check blocks
its support claim until fixed or explicitly removed from the release scope.
