### M10 — System validation and release gates

Run against features selected for the Intel/software v0.1 scope. Reuse `make test`, sanitizer builds and the
existing `make fuzz` targets for project JSON and `.cube` LUTs; extend them for new
untrusted inputs. Keep small deterministic regressions in CI and longer hardware runs
as recorded release checks.

- [ ] **Fuzzing and parser limits:** add coverage for the media probe and each implemented importer (including the shipped SRT/VTT importers). Seed valid, truncated, oversized and boundary inputs; cap input size, allocation and work. Run with ASan/UBSan, retain every reproducing crash as a regression fixture, and reject invalid input cleanly. Keep the existing project/LUT corpus and exercise project migrations as versions are added.
- [ ] **Stateful edit properties:** follow [QA timeline properties](implementation-plan-qa-timeline.md): seeded valid timelines and command streams across split/trim/move/ripple, speed maps, connected clips and undo/redo. Check independent invariants and rejected-state preservation after every step; compare every semantic state through full undo/redo and save/reload. Preserve the seed, exact replay log and minimized deterministic regression for each finding. Start with a bounded fast subset; expand command coverage without replacing M5 examples.
- [ ] **PR gate and application sanitizers:** keep the current GCC/Clang × Debug/Release/ASan/TSan matrix, format/tidy and parser-fuzz jobs; require their successful checks for merge through a GitHub ruleset. The current workflow triggers on PRs but `master` has no protection/ruleset (checked 2026-10-12), and `cmake/OmaProjectTargets.cmake` omits app/Session tests in ASan/TSan. Add a bounded, stable application sanitizer subset and state its hardware exclusions; do not claim whole-app coverage from library-only jobs.
- [ ] **End-to-end workflow tests:** automate import → edit → save → reopen → preview → export using generated video/audio and a real Omarchy recording. Check selected frames, cuts/transitions, audio continuity and A/V sync with an independent decoder; exercise keyboard navigation and a headless/offscreen GUI smoke path where possible. Run software fallback in CI and the GPU path on actual hardware. *Partial (2026-10-12)*: `tests/app/test_edit_workflow.cpp` exercises marked source placement, precise-edit undo, save/reopen and a 35-frame export checked through `ffprobe`; `test_export_snapshot.cpp` verifies the 30-frame output and original caption after an immediate project switch. The Intel/Omarchy GUI smoke passed. Selected picture/audio content, a real Omarchy recording and keyboard navigation in this exact workflow remain open.
- [ ] **Effects contract tests:** exercise schema bounds and unknown/missing versions, ordered stack evaluation, bypass/mix and shipped keyframe timing, undo/redo and old-project migration. Compare CPU/GPU output and independently decoded export at selected frames for shipped built-in effects and presets; record pass cost and memory at 1080p and 4K on each validated device. A missing pack must leave the project recoverable and never produce a silently altered export.
- [ ] **Failure and recovery tests:** inject errors at save/autosave and export write/rename boundaries and any sync boundaries actually implemented, plus full disk, missing/moved media or LUT, corrupt cache, cancelled jobs and interrupted processes. Verify acknowledged project data survives, recovery is explicit, incomplete exports are not presented as finished, and workers/resources shut down without hangs. Reuse M7's save-failure and long-export checks rather than duplicating them. *Added 2026-10-12*: `test_export_crash.cpp` kills the publisher at all five publication checkpoints, verifies both public files after recovery, checks a restarted Session's recovery action, hides live locked stages and rejects reuse of an unresolved destination. Write/sync boundary fault injection and resource stress remain open.
- [ ] **Concurrency and lifetime stress:** loop play/pause/seek, project switches, viewer resize, decode-path fallback, export cancellation and shutdown while decode/compositor/audio jobs run. Check bounded queues, deadlock timeouts and device-resource lifetime under TSan/ASan and Vulkan validation layers; test simulated device loss where supported. Record the tested hardware; do not make unavailable AMD, NVIDIA or hybrid devices a release prerequisite.
- [ ] **Audio and temporal boundaries:** compare `TimelineAudio` output across different block partitions, seek/restart and frame-aligned export boundaries with exact pulse/automation fixtures; compare preview and export PCM where their declared processing agrees. Test 23.976/29.97/59.94, 44.1/48 kHz, VFR and long source offsets at UI↔rational and keyframe interpolation boundaries. Treat drift and precision loss as hypotheses until a focused case fails.
- [ ] **Hyprland/Quickshell resize flicker gate:** instrument a dedicated visible-window resize audit with monotonic timestamps for configure/size, exposure, `frameSwapped`, scene-graph loss/error, viewer composite result and Hyprland layer/window geometry. Capture the application rectangle through the compositor during repeated tiling resizes and Projects/Edit/Settings switches; count transient blank, stale and stretched frames instead of checking only the final layout. Compare hardware decode on/off, a Qt-only Vulkan control and a reversible session with/without Quickshell at the same sizes. Diagnose which surface missed its deadline before changing the Vulkan bridge or recommending a window rule. *Partial (2026-10-11)*: `OMA_PRESENT_TRACE=1` now logs window size/visibility, `frameSwapped` and scene-graph lifecycle/errors without `grabWindow()`; a native smoke with the active `omarchy-bar` layer passed and recorded 448 frame-swap events with no scene-graph error. The smoke still checks only final-layout recovery and does not measure visible flicker. Protocol and competing hypotheses: [resize flicker research](Research/hyprland-flicker.md).
- [ ] **Sustained workload and regression measurements:** run the [long-form gate](Research/long-form-editing.md#proposed-gate-before-optimizations) plus repeated open/edit/preview/export cycles. Record frame drops, A/V drift, p50/p95/p99 and worst interaction/seek times, peak and end-of-run RAM/VRAM, file descriptors, cache/disk use and export correctness. Compare against a committed baseline for the same machine, driver and media; investigate growth or regressions before release.

**Done when**: deterministic and sanitizer suites pass in CI; bounded fuzz campaigns
pass for each shipped untrusted parser within a recorded run budget, with found crashes fixed or the affected input support removed; the edit-sequence,
workflow, recovery and concurrency checks pass on their declared paths; long-form
results and the tested hardware are recorded with fixtures, seeds, commands and versions.
Unavailable hardware and unshipped pilots are outside this gate. A failing check blocks
its support claim until fixed or explicitly removed from the release scope.
